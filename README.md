# Housing Loan Prediction


## Requirements

- [uv](https://docs.astral.sh/uv/) for dependency and environment management
- Python: uv installs the right version automatically, based on `.python-version`

To install uv:

```bash
# macOS / Linux
curl -LsSf https://astral.sh/uv/install.sh | sh

# Windows
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
```

## Installation

```bash
git clone https://github.com/manonb42/housing-loan-prediction.git
cd housing-loan-prediction
uv sync
```

`uv sync` creates a `.venv` virtual environment and installs the exact dependency versions listed in `uv.lock`.

## Data

The data is not stored in this repository. Download `train.csv`, `test.csv` and `sample_submission.csv`
from the Kaggle challenge and put them in a `data/` folder at the root of the repository:

```
housing-loan-prediction/
├── data/
│   ├── train.csv
│   ├── test.csv
│   └── sample_submission.csv
├── src/housing_loan_prediction/
└── ...
```

To read the data from another directory, change this line in
[`src/housing_loan_prediction/data.py`](src/housing_loan_prediction/data.py) (line 9):

```python
DATA_DIR = Path(__file__).resolve().parents[2] / "data"   # e.g. DATA_DIR = Path("/path/to/my/data")
```

## Code organisation

All the code is in `src/housing_loan_prediction/`. Each modelling script is run as a module from the root of
the repository:

```bash
uv run python -u -m housing_loan_prediction.<script> [step]
```

| Script | Content |
| --- | --- |
| `preprocessing.py`, `data.py` | Cleaning and feature engineering, shared by every model (see `notebooks/01_eda_preprocessing.ipynb`) |
| `evaluation.py` | 5-fold stratified cross-validation (seed 42), AUC ROC |
| `logistic.py`, `lasso_selection.py`, `submission.py` | Logistic regression, ridge, lasso; lasso submission |
| `svm.py` | Linear and RBF SVM |
| `trees.py` | Pruned decision tree and random forest |
| `gradient_boosting.py` | HistGradientBoosting (learning curves, tree size, learning rate) |
| `boosting_libs.py` | LightGBM and CatBoost |
| `stacking.py` | Out-of-fold predictions and combination of the models (mean, GES, logistic stacking) |
| `residuals.py` | Residual analysis of the final ensemble |
| `model_checks.py` | Overfitting checks: bootstrap, other metrics, confusion matrices, new fold split |

Submission files are written to `submissions/`, figures to `figures/`, and out-of-fold predictions to `oof/`
(not versioned, regenerated by the commands below).

## Reproducing the submissions

Run the commands in this order. The out-of-fold predictions of step 3 and 4 are needed by the ensembles.

```bash
# 1. Single models trained on the whole train set -> submissions/
uv run python -u -m housing_loan_prediction.submission                 # lasso_drop_sure.csv
uv run python -u -m housing_loan_prediction.trees submit               # random_forest.csv
uv run python -u -m housing_loan_prediction.gradient_boosting submit   # gradient_boosting.csv

# 2. CatBoost: learning curve on 5 folds (~35 min, writes oof/catboost.csv), then submission
uv run python -u -m housing_loan_prediction.boosting_libs curves catboost
uv run python -u -m housing_loan_prediction.boosting_libs submit catboost   # catboost.csv

# 3. Out-of-fold predictions of lasso, random forest, linear SVM and HistGB (~15 min)
#    (also writes the linear SVM submission svm_lineaire.csv)
uv run python -u -m housing_loan_prediction.stacking oof

# 4. Compare the combination methods, then write the ensembles
uv run python -u -m housing_loan_prediction.stacking compare
uv run python -u -m housing_loan_prediction.stacking submit ges moyenne logistique
#    -> ensemble_ges.csv, ensemble_moyenne.csv, ensemble_stacking_logistique.csv

# 5. Optional checks used in the report
uv run python -u -m housing_loan_prediction.residuals
uv run python -u -m housing_loan_prediction.model_checks bootstrap
uv run python -u -m housing_loan_prediction.model_checks metrics
uv run python -u -m housing_loan_prediction.model_checks refit   # ~1 h, new fold split
uv run python -u -m housing_loan_prediction.model_checks seed
```
